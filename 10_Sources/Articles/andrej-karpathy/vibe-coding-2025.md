# Vibe Coding

## Citation

Karpathy, Andrej. "Vibe Coding". X (formerly Twitter), 2 February 2025. https://x.com/karpathy/status/1886192184808149383.

## One-line summary

Karpathy coins "vibe coding" to name a practice of directing an LLM-powered coding agent by feel and voice rather than by reading or reviewing the generated code.

## Key claims

- LLMs have reached a capability level where a developer can delegate code changes entirely to an AI agent without reviewing diffs.
- Voice-to-text tools such as SuperWhisper combined with agents such as Cursor Composer enable near-keyboard-free programming.
- The practice treats code as a black box: the human specifies intent in plain English and accepts all changes.
- Error correction follows the same pattern: the user copies error messages directly into the chat rather than interpreting them.
- The resulting code can grow beyond the human's own comprehension while still functioning acceptably.
- Vibe coding is a deliberate relinquishing of control enabled by LLM reliability, not a failure of discipline.

## Excerpts

> "There is a new kind of coding I call 'vibe coding', where you fully give in to the vibes, embrace exponentials, and forget that the code even exists."
> ~ Original tweet

> ~ Original tweet

## Reveals about tendency of thought

- Coining "vibe coding" as a positive term, not a pejorative, shows Karpathy's willingness to name and endorse practices the professional community would typically discourage, consistent with his Software 2.0 thesis that LLMs replace explicit coding.
- The framing of relinquished understanding as acceptable rather than dangerous reflects his engineering pragmatism: results over process when the results check out.
- The tweet accumulating over 4.5 million views confirms Karpathy's unusual ability to crystallise latent practices into named concepts that spread instantly across the field.
